# Контролёр → одноразовый тест-агент

## Когда

Специалист сдал работу. Заказчик или контролёр просит проверку / приёмку.

## Скорость (обязательно)

Цель прогона — **минуты**, не сессия с пятью запросами «открыть браузер».

| Тип ТЗ | Как проверять (по умолчанию) |
|--------|------------------------------|
| **Дизайн / прототип / эскиз → локал** | `Read` PNG эталона + разметка/CSS компонента. Сверить композицию пунктами. Браузер **не** нужен. |
| Код / API / логика | Grep/Read + при необходимости 1–2 команды/`curl`. |
| Клики / флоу «на локале» | Только если заказчик **явно** просит runtime; максимум **один** заход в браузер (или отказ, если нет доступа — не спамить approve). |

### Запрещено тест-агенту

- Playwright / многошаговый browser loop «логин → клик → снова permission».
- Повторно просить разрешение смотреть браузер, если уже отказали или хватает эталон+код.
- «Улучшать» UI или код во время приёмки.
- Тянуть прогон дольше, чем нужно для вердикта PASS/FAIL.

Если для дизайна агент начал открывать браузер — контролёр **обрывает** и принимает отчёт по эталон+коду сам или новым лёгким агентом `explore`.

## Шаги

1. **Зафиксируй ТЗ** из сообщения заказчика (и пути к эталону). Для «перенести дизайн» ТЗ = **1:1 с LOCKED/прототипом**, не «фича работает».
2. **Запусти одного** субагента:
   - дизайн ↔ прототип → предпочтительно `explore` или короткий `generalPurpose` **без браузера**;
   - в промпте явно: «браузер не открывать; только Read эталона + файлы; отчёт за один проход»;
   - «не улучшай код; верни только отчёт»; формат ниже.
3. Дождись результата. **Не** делай `resume` этого агента на другую задачу.
4. **Решение контролёра** (заказчику, коротко):
   - PASS → «принято»;
   - FAIL → список расхождений с эталоном + «возврат: UI/UX / фуллстак».
5. Тест-агент после отчёта **удалён** (новый прогон = новый агент).

## Формат отчёта тест-агента

```text
Вердикт: PASS | FAIL | PASS_WITH_NOTES
ТЗ ↔ факт: (пункты)
Как проверено: (эталон PNG + файлы; без браузера — норма)
Расхождения: (нумерованный список vs прототип)
Риски: (кратко)
```

## Не смешивать

- Согласование отпусков в Bitrix — колокольчик, не чат (другие rules).
- Прод-деплой — только явное «ок на прод» от заказчика, даже при PASS.
