# Контролёр → одноразовый тест-агент

## Когда

Специалист сдал работу. Заказчик или контролёр просит проверку / приёмку.

## Шаги

1. **Зафиксируй ТЗ** из сообщения заказчика (и ссылки на файлы/URL). Без ТЗ — спроси 1–2 уточнения, не гоняй агента вслепую.
2. **Запусти одного** субагента (`Task`, `subagent_type`: `generalPurpose` или `explore` для ревью кода; для UI — generalPurpose с чеклистом). В промпте передай:
   - ТЗ дословно / сжато по пунктам;
   - что сделал специалист (пути, URL);
   - «проверь независимо; не улучшай код без нужды; верни только отчёт»;
   - формат отчёта ниже.
3. Дождись результата. **Не** делай `resume` этого агента на другую задачу.
4. **Решение контролёра** (пишет заказчику):
   - соответствует ТЗ → кратко итог + «принято, можно вам»;
   - не соответствует → список расхождений + «возврат специалисту: …» (какая роль).
5. Считай тест-агента **удалённым** после отчёта (новый прогон = новый агент).

## Формат отчёта тест-агента

```text
Вердикт: PASS | FAIL | PASS_WITH_NOTES
ТЗ ↔ факт: (пункты)
Как проверено: (шаги / файлы / команды)
Расхождения: (если FAIL)
Риски: (кратко)
```

## Не смешивать

- Согласование отпусков в Bitrix — колокольчик, не чат (другие rules).
- Прод-деплой — только явное «ок на прод» от заказчика, даже при PASS.
